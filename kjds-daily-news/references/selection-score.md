# 精选评分标准（内容价值）

## 0. 这个文件解决什么

四维验证和 validator 26 项管的是**来源合不合规**：域名在白名单、是具体文章页、日期格式对、底部按钮有。它们不管**值不值得看**。

所以要另有一套标准判断内容价值。本文件是唯一依据；归属裁决、去重指纹、分区归口见 SKILL.md 步骤 5 与 `跨境资讯一手信息源总表.md`。

**本版不用分数，用档位。** 理由见第十一节。

---

## 1. 执行顺序

对齐新闻编辑室的六个动作：fetch → filter → dedupe → freshness → verify → publish。

```
① 硬淘汰 → ② A 类排除 → ③ B 类降档 → ④ 定档 P0/P1/P2 → ⑤ P0 上限校正 → ⑥ 按分区配额选前 N 条 → ⑦ 档内排序
```

三个不能动的地方：

- **先排除、后定档。** 反了，好新闻的光环会把噪声带进来。
- **先验证、后判时效。** 跨境资讯经常是「旧闻新发现」——官方 10-08 发布、中文可获取是 10-20。先判时效会误杀最该收的政策类，先验证再回头看首发日。快速但错误的代价高于慢但正确的。
- **先定档、后限 P0。** 上限是「版面构型」问题，不是「这条值不值」问题。反了就是把「压数量」提前成「压质量」。

## 2. 第一步：硬淘汰（不定档，直接淘汰）

| 代码 | 条件 | 与相邻码的边界 |
|---|---|---|
| `PLATFORM_OUT_OF_SCOPE` | **平台范围外（2026-10-20 用户拍板）**：平台政策/功能/费用/招商类资讯只关注 **Amazon、Walmart、TikTok Shop** 三平台；其它平台（Temu/eBay/Shein/Shopee/Ozon/Allegro/eMAG/小红书 Redshop 等平台自身动作）**不采集、不收录**。不受此限：政府/监管与税务关务（②区）、物流商动作（③区）、跨平台行业大盘数据（④区）、社区帖（⑤区） | 平台**自身动作**才淘汰；讲某平台份额的**跨平台大盘数据**照收（④区） |
| `EVIDENCE_UNREADABLE` | 正文残缺到认不出「谁、何时、改变了什么」：只有标题、只剩导航、抓回 403 页 | 与 `TITLE_BODY_MISMATCH` 分开：前者是**读不到**，后者是**读到了但对不上** |
| `TITLE_BODY_MISMATCH` | 标题与正文核心不符。以正文为准，冲突时不得入选 | 同上 |
| `DUPLICATE_URL` | canonical_url 与已选卡片相同（同一篇） | 与 `DUPLICATE_STORY` 分开：这条比的是**链接**，那条比的是**事实** |
| `DUPLICATE_STORY` | 同一事实**已在往期早报报过，且本期无新进展**——新公告/新细则/新截止日/新数据均算有新进展（见 SKILL.md 步骤 3.1 零成本硬淘汰与 `topic-registry.md`） | 见下方 A7 的边界说明 |
| `OUT_OF_DATE_WINDOW` | 首发日**无法确认**，且页面带有明确早于窗口的日期证据（正文日期、转载页标注的旧日期），导致无法验证落在窗口内。单纯的「日期存疑」按发现日处理，**不淘汰** | 与 §8 的时效口径同源：窗口是排序权重不是淘汰门槛，此码只用于「日期既无法确认、又有反证」 |
| `SPECULATION` | 只有传闻、预测、内部消息，无可核验的已发生事实 | 与 `B3`（二手转述无法溯源）分开：B3 有事实但溯源不到，此码**连事实都没有** |

> ⚠️ **审计里还会出现、但不属于本表的代码**（四维验证阶段产生，不在内容门禁范围）：
> `NO_PRIMARY_OR_ORIGINAL_SOURCE`（溯不到首发）、`URL_UNREACHABLE`（实测 404）、`DATE_UNCONFIRMED`（页面无时间戳）、
> `NOT_ARTICLE_PAGE`（只有列表页无具体文章）、`CONTENT_MISMATCH`（正文与标题/摘要矛盾）、`LOW_SELLER_RELEVANCE`（与卖家经营无关）。
> 这些在**淘汰记录表**里如实写明即可，不要硬套本表的 7 个码。

## 3. 第二步：A 类排除（有信息但不构成卖方情报，排除）

命中即排除，不定档，不进配额。审计记 `淘汰:A编号`。

| 编号 | 条件 |
|---|---|
| A1 | 服务商、工具商、招商加盟、课程培训的推广；通篇引导留资、加群、领资料 |
| A2 | 多事件打包的周报/月报/资讯合集/榜单，无单一焦点 |
| A3 | 纯预告、「即将推出」「敬请期待」，无生效日期、无费率、无适用范围 |
| A4 | 与跨境卖家经营无关的泛科技、泛财经、国内电商、消费电子评测 |
| A5 | 终端消费者层面的产品测评、达人种草、开箱 |
| A6 | 纯人事任命、会议召开、协会成立，无已兑现的规则后果 |
| A7 | **本期内部**的同一事件多篇报道，且不含已选卡片没给过的具体信息（跨期的同一事件已在硬淘汰 `DUPLICATE_STORY` 处理） |
| A8 | **汇率日评、运价指数日更**（SCFI/WCI/FBX 每日点位）。仅当单周波动 >10% 或趋势反转时作为 P1 收一条 |
| A9 | **第三方「政策解读」「新规拆解」稿**，本身不是发布载体。原文本已在总表 T0 可取的，一律用原文 |
| A10 | **物流商报价促销**（「美森特价」「空派 3 折」）。运价水平变化走 A8 口径，促销不做新闻 |

A8/A9/A10 是跨境资讯的主要噪声源，占比高于其他任何一类。A9 尤其要卡死：四维验证只保证链接落在原文域名，管不住「原文本身就是二手解读」。

**A7 与硬淘汰 `DUPLICATE_STORY` 的分界**（两者都是「重复」，混用会导致审计归因错误）：

| | `DUPLICATE_STORY`（硬淘汰） | A7（A 类排除） |
|---|---|---|
| 重复发生在 | **跨期**：往期早报已报过 | **本期内部**：同一批候选里多篇报道同一事件 |
| 判定依据 | topic-registry 记的是同一事实，本期无新进展 | 多篇里只有一篇有实质增量，其余是改写/转述 |
| 审计写法 | `[淘汰] DUPLICATE_STORY \| … \| 往期已报` | `[淘汰] A7 \| … \| 本期重复报道，无增量` |

## 4. 第三步：B 类降档（有真信息但价值有限，最高只能到 P2）

命中时**该条最高只能定 P2**，无论其他理由多充分。P2 只能用来补某分区没有 P0/P1 的空位。

| 编号 | 条件 | 降档 |
|---|---|---|
| B1 | 平台例行小版本、常规功能补齐、语言/地区扩展、普通 UI 调整、非卖家侧的开发者更新 | 最高 P2 |
| B2 | 客户案例、联合解决方案、「某卖家如何用某工具」，无规模/成本/时间/可迁移方法 | 最高 P2 |
| B3 | 二手转述无法溯源到原始公告；只有「某机构称」「据业内人士」而无比具体出处 | 最高 P2 |
| B4 | 来源是第三方解读而非发布载体（与 A9 的区别：A9 是只转述无增量，B4 是有一手采写但非原文） | 最高 P2 |

## 5. 第四步：定档 → 第五步：P0 上限校正

> 本节含执行顺序的第 ④ 步（定档）与第 ⑤ 步（P0 上限校正）。两步不可颠倒：上限是「版面构型」问题，不是「这条值不值」问题。

**定档只回答一个问题：卖家明天要不要改做法。** 不回答「这事大不大」「谁发的」「写得多好」。

| 档 | 含义 | 版面地位 |
|---|---|---|
| **P0** | 卖家明天必须改做法 | 头条与看点 |
| **P1** | 有明确影响，但不用明天动手 | 正文主体 |
| **P2** | 有信息量的背景与趋势 | 补空位 |
| 淘汰 | 见第二、三节 | 不进版面 |

### P0 判据（满足任一）

- 费率、佣金、仓储费、广告费的数值或计算方式变更，**且生效日在 30 天内**
- 强制性合规要求生效或执行口径变更：CPSC 召回、FDA/CE/FCC、EPR/PPWR、关税、申报模式（0110/9810）、VAT
- 截止日进入 30 天内：入仓截止、税务申报、征求意见截止、应诉期限
- 平台规则变更且**带处罚后果**：账户状况、Listing 下架标准、封店口径、**账户状况评级算法调整、绩效指标阈值变动**、达人/卖家等级分层规则
- 大范围履约中断：港口罢工、航线停摆、清关政策突变、主要仓爆仓

> ⚠️ **P0 的时间锚点（v2.9.0 补）**：判据里所有「生效」「截止」都带 **30 天窗口**，超出窗口的降到 P1。
> 原因：P0 的定义是「卖家**明天**必须改做法」，一条 90 天后才生效的费率变更不需要明天动手——今天知道是为了 3 个月后调整定价留出余量，那是 P1 的信息。
>
> | 情形 | 档 |
> |---|---|
> | 旺季附加费公布，**10-15 生效**（run_date 10-01，14 天后） | **P0** |
> | 仓储费上调，**明年 1 月 1 日生效**（3 个月后） | **P1** |
> | 征求意见截止 **10-25**（5 天后） | **P0** |
> | 合规整改窗口在 **6 个月后** | **P1** |
>
> **例外**：带处罚后果的规则变更、召回、履约中断**不受 30 天限制**——它们一旦发生就是当下的风险，与生效日远近无关。

### 超过 30 天窗口的统一处理

| 情形 | 最高档 |
|---|---|
| 费率/费用类变更，生效日 >30 天 | P1 |
| 合规类要求生效或整改窗口 >30 天 | P1 |
| 征求意见稿、预告类（无生效日） | P1（须有全文和明确时间表，否则 P2） |
| 已生效且带处罚后果的规则变更 | **P0**（不受窗口限制） |
| 召回、履约中断、港口停摆 | **P0**（不受窗口限制） |

> 窗口外的政策**不丢弃**——它们进临近节点时间线（`timeline-section`），到临近时再作为 P0 报出。这是 §8「时效以首发日为准」与本节「30 天窗口」两条规则的分界：**首发日决定能不能收，30 天窗口决定算不算 P0。**

### P1 判据（满足任一）

- 平台新功能、新工具上线，卖家可直接用
- 流量分配或搜索排序机制发生变化
- **大盘/竞品/品类数据变化，且原文直接指向卖家的一个具体经营决策**（改定价、改备货量、改选品、改广告预算），并给出可据以行动的依据
- 政策征求意见稿或未生效规则，**但有全文和明确时间表**

> ⚠️ **P1 必须是「卖家要动一下」而非「卖家该知道」**（v2.9.0 收紧）。
> 只有数字和口径、读完不知道该改什么的（品类集中度、全站 GMV、份额变化、行业规模）一律 **P2**。
> 7 期回归实测：收紧前 P1 占 33/86 = 38%，档位退化成「P1 = 正常新闻」，区分度归零。

### P2 判据（满足任一）

- 有方法说明的行业调研、趋势分析
- **品类需求数据出现方向性变化（有具体数字和口径，但不指向具体决策）**
- **大盘或竞品格局变动，附具体数据（纯背景）**
- 平台招商、扩张的宏观信息
- 生态与服务商的重要变动（非推广）
- 与卖家经营间接相关的宏观数据
- 命中 B 类降档，但确有上述任一信息量

### 锚定例子（判档时对照，不要自由发挥）

| 材料 | 档 | 判据 |
|---|---|---|
| FBA 旺季附加费公布，10-15 生效 | P0 | 费率 + 生效日（14 天内） |
| 仓储费上调，明年 1-1 生效 | P1 | 费率变更但生效日超 30 天窗口 |
| 海关总署 1210 跨关区退货征求意见，10-25 截止 | P0 | 截止日 30 天内 |
| CPSC 对某类 LED 产品发布召回 | P0 | 强制合规 + 带后果 |
| 亚马逊上线多渠道销售工具，可接沃尔玛/Shopify | P1 | 新工具可直接用，无强制动作 |
| Marketplace Pulse 发布某品类集中度数据（无行动指向） | P2 | 纯背景大盘数据 |
| 某品类集中度数据显示头部 10% 卖家吃掉 59% 份额，并指出低份额卖家应重投该品类广告 | P1 | 数据直接指向广告预算决策 |
| 亚马逊后台新增多语言筛选（B1） | P2 | 例行功能，最高 P2 |
| 某服务商发布「旺季广告投放白皮书」 | 淘汰:A1 | 推广 |
| 某大卖财报超预期 | P1 | 竞品格局，有数据 |
| 汇率日评「今日人民币小幅走弱」 | 淘汰:A8 | 日内点位 |
| 「新关税政策深度解读」非原文 | 淘汰:A9 | 二手解读 |

### P0 上限校正 = 第五步（v2.9.0 新增，治「政策多发日版面被占满」）

**单期 P0 不超过该期最终卡片数的 40%**（向下取整，最少 1 条）。

- **计算基数 = 该期最终卡片总数，含社区卡**（14 卡里 3 张知无不言 → 基数 14，上限 5 条）
  社区卡是版面的一部分，压缩 P0 时不能把基数排除——否则「多报 3 条社区帖」就能变相抬高 P0 上限
- **只有 `[P0]` 行计入 P0 计数**，`[P1]` / `[P2]` / `[社区]` 都不计入。`[社区]` 只是一条记录标签，不代表档位，不参与任何档位比较
- 10-16 期实测 6 条 P0（假日大促 / NWD 移除 / 两条 CPSC / 金税四期 / 霍尔木兹海峡）全收会挤掉物流与市场分区
- 超限时的处理：**不是删卡片，是降档**。按「受影响卖家数量 × 是否需明天动手」排序，受影响面最小者降为 P1 进版面，卡片内容不变
- 判定顺序：**先定 P0 全部候选 → 算 P0 上限 → 超限者降 P1 → 再走分区配额**
- 降档是**记录在审计里的显式动作**，不是静默截断

> P0 上限只压数量，不压质量：一条真正「明天必须改做法」的内容不该因为同一天还有 4 条 P0 就被丢掉，只是让位为 P1 呈现。

## 6. 第六步：分区配额（版面构型）

> 执行顺序：① 硬淘汰（§2）→ ② A 类排除（§3）→ ③ B 类降档（§4）→ ④ 定档（§5）→ ⑤ P0 上限校正（§5）→ **⑥ 分区配额（本节）** → ⑦ 档内排序（§7）

日报是版面，不是排行榜。所以按分区挑，不按全局分数取前 N。

| 分区 | 基础配额 | 说明 |
|---|---|---|
| ① 平台政策与费用 | **3–6** | 下限 3：**Amazon / Walmart / TikTok Shop 各至少 1 条**；上限 6。区内按平台分组排序（Amazon → Walmart → TikTok Shop），单平台超 3 条时第 4 条起须为 P0 或带处罚后果的规则变更，否则让位。费用类可在区内独立成组 |
| ② 合规与监管 | **3–4** | P0 高发区，上限 4；超出按「受影响卖家数 × 是否需明天动手」取舍，其余降档 |
| ③ 物流与供应链 | **2–4** | 上限 4。运价类按 A8 口径 |
| ④ 行业与市场 | **2–4** | 上限 4。纯数据类多落 P2，达上限后不再加条 |
| ⑤ 卖家社区 | **3**（固定） | 上限 = 下限 = 3。知无不言按热度硬选 3 条，多出的一律不收；验证通过不足 3 条时允许少报，须在审计注明 |
| **合计** | **13**（下限）→ **21**（各区上限加总） | 与 SKILL 5.5 的 13–21 一致；shortlist **38**（②③④⑤ = 上限×2；**① 例外取 8 而非 12**，三平台各 2-3 条候选已够覆盖） |

规则，按顺序执行：

1. 先填每个分区的 P0（**已受 P0 上限约束，见 §5 的 P0 上限小节**——② 区一天出 5 条 P0 就收 5 条的前提是全局 P0 未触顶）
2. 再填 P1 至基础配额
3. ① 区先按「三平台各 1 条」铺底，再用 P0/P1 填到上限 6
4. 各区**达上限即停止加条**，多余 P0/P1 按 ② > ① > ③ > ④ 的优先级让位，实在排不进就降档并写 `audit_note: 降档:该区达上限`
5. 空位补不上就用 P2，P2 也只能补到该区配额
6. 全部分区都不足时按实际数量出，不足 7 条在审计说明原因，**不为凑数降档**
7. **① 区缺口**：某平台当日无已通过四维验证的资讯 → 审计写 `①区缺口:<平台名>`，用其余两平台补到 ①≥3。**不得用转载、旧闻、服务商解读凑覆盖**——覆盖要求不构成降低验证标准的理由

> **P0 上限与配额的关系**：P0 上限（≤40%）是全局总量约束，配额是分区内约束。两者都满足才算版面合规。
> 触顶时的降档在 §5 的 P0 上限校正步已完成（进配额前就已是 P1），所以本步的 P0 计数天然不超限。

## 7. 第七步：档内排序

同档同分区内，按顺序比较：

1. **时效**：当日 > 昨日 > 前日（以首发日计，见第八节）
2. **影响面**：受影响的卖家范围更广的靠前
3. **有时限的靠前**：P1 里带截止日的优先于纯信息
4. **画像匹配**：健康个护、FBA 费用与仓储、广告与 ACOS、Q4 备货、FDA/CE/FCC 合规（示例关键词，按自己类目替换）

画像只用于排序，不改变档位。**来源等级（T0/T1）不参与排序**——那是四维验证的职责，不该在内容层再算一次。

## 8. 时效口径：以首发日为准

**首发日** = 该事实第一次出现在原始发布载体的日期，不是中文转载日，也不是你发现它的日期。

| 情形 | 处理 |
|---|---|
| 首发日在窗口内 | 正常排序 |
| 首发日在窗口外，但今日才发现 | 不扣价值，按当日处理，卡片标注实际首发日 |
| 首发日无法确认 | 按发现日处理，审计注明「日期存疑」 |
| 同一事实有新进展 | 按新进展的首发日算，摘要注明「延续报道」 |

跨境时滞是结构性的，不是新闻质量差。10-20 期那条沃尔玛企业新闻首发 10-08、中文可获取 10-20，按「隔天扣分」的算法它会被砍掉，而它恰恰是当期有效信息。

窗口（`[date_from, date_to]`）只决定采集范围与排序权重，不是淘汰门槛。唯一的窗口类淘汰是 `OUT_OF_DATE_WINDOW`：首发日无法确认、且页面带有明确早于窗口的日期证据（正文日期、转载页标注的旧日期）导致无法验证落在窗口内；单纯的「日期存疑」按发现日处理，不淘汰。

**不用时间衰减公式**（如 HN 的 `(votes-1)^0.8/(age+2)^1.8`）：那解决的是「海量候选里谁排前面」。我们每天只有 30–50 条候选、窗口本来就只有 2–3 天，衰减曲线在这个量级上不产生有效区分，只会误杀。

## 9. 社区帖独立口径

知无不言、Reddit 不套主档位——个人经验天生判不出「卖家明天要不要改做法」，硬套必然全砍，但社区价值恰恰在经验本身。

社区帖按下列判：

- **可复用性**：能否直接照着改 Listing/广告/库存做法
- **具体度**：有无店铺数据、后台截图、可验证的前后对比
- **对应时点**：是否对上正在发生的政策或旺季节点

知无不言精华帖按浏览数 + 关注人数硬选 3 条，同热度段内优先运营实操（广告/Listing/库存/合规），通用闲聊靠后。标签统一「知无不言」，不参与 T0/T1 排序。3 条是配额强制项而非可打折的目标，但验证通过不足 3 条时允许少报——必须在审计写明已检查渠道与缺口，不得用低质帖凑数。

> **审计里写 `[社区]`**：这是**记录标签**，不是档位。社区帖不参与 P0/P1/P2 比较、不计入 P0 上限的 P0 计数（但计入卡片数基数），只是为了让「定档行数 == 卡片数」这条门禁能覆盖到社区卡。详见 §12。

## 10. 绝不能当加分项的东西

以下与内容价值无关，不得因为它们给分或提档：

- 大厂、上市公司、头部大卖、知名机构发布（这是**光环效应**，B 类降档和各档判据都在防它）
- 正文长、术语多、数字多、有图表
- 标题有「重磅」「首次」「最大」「唯一」「创纪录」「重新定义」
- 原文是英文（翻译难度不是价值）
- 很多家都在报道（那是热度，不是价值；重复报道走 A7）

反过来也不能扣分：正文短、中文源、小平台官方公告、只有一段话的生效通知。信息密度看内容，不看篇幅。

## 11. 为什么不用分数

上一版三轴各 0-3、满分 9、底线 ≥5，已废弃，不要改回去：

- **绝对分会聚集**：模型把样本堆在中间档，0-3 只有四格更严重，三轴实际退化成单轴。缓解靠档位锚定加例子，不靠细分量程。
- **门槛管不了版面**：日报是从 30–50 条挑 13–21 条的有界选择，分数只说「够不够格」，说不了「今天这 13 个位置怎么分」。
- **成对比较不可行**：40 条候选是 780 次比较，成本不接受；拟合 Bradley-Terry 还原连续分是过度工程。

真正起作用的硬约束是 **A 类排除 + B 类降档 + 分区配额**——它们不依赖模型自评的稳定性。

## 12. 审计记录格式

**两套格式，各管一段**（v2.9.0 明确，此前混用导致 validator 与人工审计对不上）：

| 内容 | 格式 | 理由 |
|---|---|---|
| **入选卡片** | 行格式 `[档位] 分区符号 \| 标题 \| 备注` | validator 要机器解析行首与分区符号，必须逐行独立成行 |
| **淘汰候选** | 表格格式 `\| 候选 \| 代码 \| 说明 \|` | 淘汰项数量多、说明长，表格可读性远好于行格式；且不参与任何计数校验 |

### 入选行格式（validator 校验，逐行独立成行）

```
[P0] ① 平台政策 | FBA旺季附加费10-15生效 | 排序:当日/影响全站
[P1] ③ 物流 | Maersk欧线PSS调整 | 排序:昨日
[P2] ① 平台政策 | 后台多语言筛选 | 降档:B1
[P1] ② 合规监管 | 某批次召回 | 降档:P0超限→P1
[社区] ⑤ 卖家社区 | 知无不言125560 差评后流量暴跌 | 可复用性/具体度/对应时点
```

- 档位取值：`P0` / `P1` / `P2` / `社区`。**社区帖写 `[社区]`**，不套 P0/P1/P2（第九节独立口径）——此前规格未定义社区帖的档位写法，导致含社区卡的审计无法通过「定档行数 == 卡片数」门禁
- 分区符号必须与卡片实际所在分区一致：`①` 平台政策与费用 / `②` 合规与监管 / `③` 物流与供应链 / `④` 行业与市场 / `⑤` 卖家社区
- **入选行数必须等于报告卡片数**（validator 校验）
- **各分区的入选行数必须等于该分区实际卡片数**（validator 校验，code=AUDIT_ZONE_MISMATCH）
- **P0 行数 ≤ 卡片数 × 40%**（最少 1 条，validator 校验，code=P0_RATIO）
- **入选行不写淘汰代码**——淘汰是另一段的事，别把两件事塞进一行

### 淘汰行格式（表格，不参与计数）

```markdown
## 四、淘汰记录（逐条原因代码）

| 候选 | 代码 | 说明 |
|------|------|------|
| cifnews 189503《亚马逊将推出 Listing Protection》 | `NO_PRIMARY_OR_ORIGINAL_SOURCE` | 页脚「（来源：董海温）」→ 跨站转载，须溯首发，未取得 → 淘汰 |
| 某号「新关税深度解读」 | `A9` | 二手解读，原文已在总表 T0 可取 |
```

- 代码取 §2 硬淘汰码（7 个）或 §3 A 类编号（A1–A10）、§4 B 类编号，或四维验证阶段的码（`NO_PRIMARY_OR_ORIGINAL_SOURCE` / `URL_UNREACHABLE` / `DATE_UNCONFIRMED` / `NOT_ARTICLE_PAGE` / `CONTENT_MISMATCH` / `LOW_SELLER_RELEVANCE`）
- **说明必须写清「为什么被拦」**，不允许「其他原因」

审计必须能回答「这条为什么没进、被哪条规则拦的」。

**降档必须留痕**：B 类降档写 `降档:B编号`，P0 上限降档写 `降档:P0超限→P1`。validator 会校验入选行数与卡片数一致，但降档原因靠人写——这是唯一能回溯「为什么这条不是头条」的地方。

## 13. 校准

改了本标准后，拿历史期回归：

1. 取最近 7 期已交付报告的全部卡片 + 当期淘汰记录
2. 逐条按本文件重新定档，看哪些原本入选的会被砍、哪些原本淘汰的该入选
3. 砍掉的都是你认为该砍的 → 标准可用
4. 砍掉了你认定的重要新闻 → 是某档判据没写清，补判据和例子，**不要放宽配额**
5. 几乎没砍掉东西 → A/B 清单没起作用，检查执行顺序是不是反了（先定档后排除）

**先改判据，再调配额。** 配额只能整体移动，解决不了「哪一类判错了」。

**三类判据要分开校准（别混在一起看）**：

| 校准对象 | 看什么 | 合格信号 |
|---|---|---|
| **A/B 类清单** | 回归后砍掉几条 | 砍掉的都确实是噪声。**7 期实测只砍 2 条**——这不是清单失效，是 A 类管内容、白名单管来源，两者本就不重叠，别因为"砍得少"就放宽 A 类 |
| **档位区分度** | 回归后 P0/P1/P2 的分布 | **P1 不应超过 40%**。7 期实测收紧前 P1 占 38%，退化成了「P1 = 正常新闻」，这是档位制最典型的失败模式——看起来分了三档，其实只有两档 |
| **P0 上限** | 有多少期触发降档 | 触发降档的期数应 < 1/3。**每期都触发**说明上限过紧或 P0 判据过松（先改判据，别动上限） |

**校准顺序**：先看档位分布（区分度）→ 再看 P0 上限触发率 → 最后才看 A/B 清单砍了几条。反过来会被"砍得少"的表象误导去放宽排除标准。
